# モデル・ルーティング・ポリシー

原則: **司令塔は常に最高性能モデル。作業者はタスクの不可逆性×難易度で切替。**
モデル名は環境に合わせて `MODEL_MAP` を書き換えて流用する。

**運用の要点（2026-08-31 追記・実務で確認）**:
**プランニングと品質チェックは Opus か Fable（T1）が行い、単純作業は Sonnet（T2）の
サブエージェントへ積極的に委譲する。** メインセッションの文脈は有限なので、
**手を動かす量が多い作業を T1 が自分でやると、判断に使える文脈を消費して質が落ちる**。
委譲は節約のためだけでなく、**T1 を判断に専念させるため**でもある。

## MODEL_MAP(環境ごとに差し替え)
| ティア | 想定モデル例 | 用途 |
|---|---|---|
| T1 (Frontier) | Claude Opus / Fable 級 | 司令塔・PM裁定・アーキテクチャ・Consultant反証 |
| T2 (Balanced) | Claude Sonnet 級 | 実装・レビュー・ドキュメント・UIUX設計 |
| T3 (Fast) | Claude Haiku 級 | 整形・要約・ログ蒸留・grep的探索・定型QAチェック |

## Orchestrator の実体(Claude Code)
Orchestrator はサブエージェントではなく**メインセッションそのもの**。`.claude/settings.json` の `model` で T1 に固定済み。
PMが「何を作るか」を裁定し、Orchestratorが「議論をどう回すか(招集・文脈配布・想起・蒸留・モデル采配)」を担う。

## 切替の判断基準
- **不可逆性が高い**(データモデル、公開API、料金設計)→ T1
- **やり直しが安い**(UIコピー、内部ツール、ログ整形)→ T3
- 迷ったら T2。コスト超過が見えたら Orchestrator が一段下げ、品質劣化を QA が監視

## 実装上の対応
- Claude Code なら: サブエージェント定義(`.claude/agents/*.md`)の `model:` フィールドにティアを反映
- API直なら: ループ実行スクリプトでロール→model文字列を解決

## 委譲の実務（2026-08-31・実際に回して分かったこと）

### T1 が手放さないもの

- **何を作るか・どの順で回すか**の決定（プランニング）
- **結果の判定**（品質チェック）——サブエージェントの報告を鵜呑みにしない。
  実際に**誤った報告を受けた**ことがある（「Multipaz はバッチ発行に未対応」→ソースを
  読むと対応済み。「suite 側の例外」→全実行を横断すると測定ドライバの制約だった）
- **仕様の解釈**と、**原文を引いて仕分ける**判断
- **不可逆な操作**（履歴書き換え・本番の設定変更・失効）

### T2 へ委譲してよいもの

**「何をどうするか」が決まっていて、手数が多いもの**。

- 決まった仕様どおりの実装＋テスト（例: `x509_hash` の追加）
- 大量の実行と集計（例: 適合テスト 63 モジュールを1件ずつ回して表にする）
- 網羅的な実測（例: セキュリティ観点 22 項目のプローブ）

### 委譲するときの指示の作り方

**ここを手を抜くと、返ってくるものが使えない。**

1. **調査済みの事実は渡す**（再調査させない）。仕様の引用・確定した設定値・既知の落とし穴
2. **判定させない**。「問題なしと書かないこと」「観測した事実だけを書くこと」と明示する
   ——判定を混ぜられると、どこまでが観測でどこからが解釈か分からなくなる
3. **やってはいけないことを列挙する**。デプロイしない／コミットしない／本番を叩かない／
   コードを直さない。**「直そうとしない」は特に効く**——直されると原因が消える
4. **報告の形を指定する**。項目番号・期待する粒度・省略してほしくないもの（生のメッセージ）
5. **期待値を書かない**（先入観を持たせない）。「HTTP 200 が返るはず」と書くと
   そう報告されることがある

### 委譲の落とし穴

- **完了報告が来ないことがある**。「バックグラウンドで開始しました」だけで終了した例が
  あった。**リポジトリや外部の状態を自分で確かめる**（`git status` / API を叩く）
- **並列に増やしすぎない**。同じファイルを触る委譲を重ねると衝突する。
  適合テストは plan の alias を共有するので**1件ずつ**回す必要があった
- **T3（Haiku 級）は要約・整形に留める**。実測や仕様解釈を任せると精度が足りない
